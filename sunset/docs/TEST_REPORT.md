Проверены все пять Maven-модулей: API Gateway, Auth, Order, Product и Notification. Добавлены отрицательные тесты подмены `user-id`, границы публичного URI и привязки уведомления/подписки к доверенному пользователю. После установки на `http://192.168.1.186` прошли все восемь безопасных smoke-сценариев; все backend-контейнеры и PostgreSQL имеют статус `healthy`.

## Исправленные проблемы тестовой инфраструктуры

- Стандартный CRA-тест искал удалённый текст `Learn React` и всегда падал; заменён проверкой реального интерфейса.
- `react-router-dom` 7 не разрешался старым Jest из `react-scripts`; зависимость зафиксирована на совместимой версии 6.30.1. Используемый API приложения с ней совместим, production-сборка успешна.
- Maven не задавал UTF-8, поэтому русские строки компилировались платформозависимо; в родительский POM добавлена явная кодировка.
- Maven-кеш внутри OneDrive блокировал JAR-файлы на Windows; общий скрипт использует пользовательский `.m2` вне проекта.
- Notification Service не имел тестовой зависимости; добавлен `spring-boot-starter-test`.
- Из CartContext удалены отладочные `console.log`.
- Smoke-сценарий сделан совместимым с Windows PowerShell 5.1 и корректно декодирует бинарное представление JSON-ответа Actuator.

## Найденные риски, не устранённые автоматически

1. `npm audit` сообщает 64 уязвимости транзитивных зависимостей: 14 low, 14 moderate, 33 high, 3 critical. Основной источник — устаревший `react-scripts`; слепой `npm audit fix --force` не применялся, поскольку может сломать сборку. Целевое исправление — миграция на Vite и обновление зависимостей.
2. Spring-контекст предупреждает о тестовом PostgreSQL dialect поверх H2 и включённом Open Session in View. Для точной проверки SQL нужны Testcontainers с PostgreSQL 16.
3. Текущие unit-тесты Order Service проверяют защитные правила, но не доказывают атомарность начисления/компенсации бонусов на реальной БД.
4. Нет браузерного E2E для оформления заказа и админского подтверждения; это следующий приоритет.
5. Smoke-набор намеренно не создаёт пользователей и заказы на production-сервере, поэтому остаётся безопасным и не меняет бизнес-данные.

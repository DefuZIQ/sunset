## Дополнение от 4 октября 2026 года

После восстановления доступа к серверу тесты Auth и Product Service выполнены на PostgreSQL 16: 4/4 без ошибок. Проверены конкурентная покупка последнего экземпляра двумя клиентами и четыре HTTP-контрактных сценария Gateway с временным downstream-сервером. Полный backend Maven reactor завершился с результатом 47/47. Тестовые исходники загружены в каталог проекта на сервере; работающие образы сервисов не менялись, поскольку производственный код этого этапа не затронут.

Дополнительно выполнен 1/1 opt-in HTTP E2E: четыре реальных сервиса запущены локально, база PostgreSQL 16 — в отдельном временном контейнере с SSH-туннелем. Проверены регистрация, каталог, заказ, идемпотентный повтор, подтверждение администратором, начисление и компенсация бонусов, восстановление остатка после отмены и отказ гостю. После теста локальные сервисы, туннель и временная база остановлены; рабочая база магазина не использовалась. Сценарий подключён к GitHub Actions, но удалённый запуск CI ещё не подтверждён.

## Исправленные проблемы тестовой инфраструктуры

- Стандартный CRA-тест искал удалённый текст `Learn React` и всегда падал; заменён проверкой реального интерфейса.
- Frontend перенесён с Create React App/Jest на Vite 7/Vitest 4; React Router обновлён до защищённой версии 7.18.4.
- Maven не задавал UTF-8, поэтому русские строки компилировались платформозависимо; в родительский POM добавлена явная кодировка.
- Maven-кеш внутри OneDrive блокировал JAR-файлы на Windows; общий скрипт использует пользовательский `.m2` вне проекта.
- Notification Service не имел тестовой зависимости; добавлен `spring-boot-starter-test`.
- Из CartContext удалены отладочные `console.log`.
- Smoke-сценарий сделан совместимым с Windows PowerShell 5.1 и корректно декодирует бинарное представление JSON-ответа Actuator.

## Найденные риски, не устранённые автоматически

1. Миграция с `react-scripts` на Vite завершена. `npm audit` для полного дерева и production-зависимостей сообщает 0 уязвимостей.
2. Старые smoke-тесты Spring-контекста всё ещё используют H2; критический SQL заказов теперь отдельно проверяется на PostgreSQL 16 через Testcontainers.
3. Единый HTTP E2E через Gateway, реальные Auth/Product/Order Service и временную PostgreSQL реализован для самовывоза. Следующий уровень — браузерный сценарий доставки, адресов и платёжного webhook после появления реальной интеграции.
4. Базовый браузерный E2E-контур покрывает каталог, фильтры, поиск, выбор размера, корзину и защиту админки; он использует детерминированные API-ответы.
5. Smoke-набор намеренно не создаёт пользователей и заказы на production-сервере, поэтому остаётся безопасным и не меняет бизнес-данные.

# Форма добавления товара в админке

Дата: 21 октября 2026.

Убрана узкая постоянно раскрытая форма рядом со списком товаров. Добавление открывается отдельной кнопкой и занимает всю ширину рабочей области. Поля сгруппированы по смыслу: информация о товаре, раздел и изображение. Есть предпросмотр фотографии и понятная ошибка при незагрузившейся ссылке. На телефоне секции идут одна под другой. Новая карточка не создаётся без выбора конечной подкатегории; смена аудитории сбрасывает прежнюю категорию.

Исходный стартовый остаток `10` и готовое фото первого товара убраны: новая карточка начинается с нулевого остатка и пустого поля фотографии, чтобы не публиковать случайно дублированное изображение или фиктивный запас. Поле количества теперь явно сообщает, что значение применяется **к каждому размеру на складе**; отдельные магазины и размеры после создания настраиваются в разделе «Остатки». Загрузка файла изображения в этой итерации не добавлена — пока требуется ссылка на фото.

Изменён только фронтенд. API и схема БД не менялись. Проверки: `npm run typecheck`, `npm run build`, 74 unit-теста, полный Playwright-набор — 123 passed, 11 skipped. Тест создания проверяет обязательную подкатегорию, аудиторию, фото и нулевой остаток. Реальную запись в рабочую БД тестами не создавали.

Локальный релиз `192.168.1.186`: `sunset-web:candidate-admin-product-form-20261021`; предыдущий образ сохранён как `sunset-web:rollback-admin-product-form-20261021`. Публичный релиз: `/srv/sunset/releases/admin-product-form-20261021`; предыдущий `/srv/sunset/releases/admin-workspace-20261021b` сохранён. После публикации локальный и публичный desktop/mobile live smoke прошли.

Откат: на VM пометить `sunset-web:rollback-admin-product-form-20261021` как `sunset-web:latest` и пересоздать только `web` через Compose без сборки. На VDS атомарно переключить `/srv/sunset/current` обратно на `/srv/sunset/releases/admin-workspace-20261021b`. Затем проверить `/` и `/admin/`.

# Аудит зависимостей — 11 октября 2026

Источник: [OSV-Scanner в GitHub Actions](https://github.com/DefuZIQ/sunset/actions/runs/38156770430), коммит `acfe988`. Сканирование отчётное (`fail-on-vuln: false`): успешный job означает, что скан завершился, **не** что зависимостей без уязвимостей. Проверены Maven `pom.xml` и npm lockfile; OSV строит транзитивный граф Maven. Это список известных совпадений версий, а не подтверждение эксплуатируемости каждого CVE в приложении.

## Базовая линия

- 237 срабатываний, 167 уникальных идентификаторов, 69 затронутых пакетов по выводу сканера: 16 Critical, 95 High, 100 Medium, 24 Low, 2 Unknown. Один результат относится к frontend dev-зависимости, остальные — к Maven-манифестам. Повтор одного CVE в разных модулях учитывается несколько раз.
- В собранных JAR локального релиза обнаружены: Gateway — `spring-webflux 6.0.12`, `spring-security-web 6.1.4`, `netty-handler 4.1.97.Final`, `bcprov-jdk18on 1.73`; остальные четыре сервиса — `tomcat-embed-core 10.1.39` и `spring-webmvc 6.2.5`. Таким образом, ключевые Maven-версии отчёта присутствуют в собираемых приложениях; степень применимости конкретных CVE требует отдельной проверки.
- Причина значительной части долга: в корневом BOM закреплён Spring Boot `3.4.4`, а Gateway отдельно переопределяет его на `3.1.4` и Spring Cloud на `2022.0.4`. По [таблице совместимости Spring](https://spring.io/projects/spring-cloud/) ветка Cloud `2022.0.x` относится к Boot `3.0/3.1` и завершила OSS-поддержку.
- Frontend: `source-map-js 1.2.1` находился только в dev-зависимостях. Lockfile обновлён до исправленной `1.2.2`; `npm ci`, 61 unit-тест, typecheck и сборка прошли. Это изменение не требует отдельной публикации сайта: пакет используется при сборке, не входит в запущенный frontend-бандл.

## Приоритет работ

1. Отдельно обновить Gateway на поддерживаемую совместимую пару Spring Boot/Spring Cloud. Не смешивать старый Gateway BOM с новым корневым BOM; сначала проверить компиляцию, JWT/маршрутизацию и HTTP-контракты на изолированной PostgreSQL.
2. Корневой Spring Boot BOM для Auth, Product, Order, Notification и API Contract обновлён до `3.5.16`, пройдены тесты и установка ([релиз](RELEASE_20261011D.md)). [Spring Boot 3.5.16](https://spring.io/blog/2026/06/25/spring-boot-3-5-16-available-now/) — последний OSS-релиз своей ветки, поэтому для устойчивого решения нужно оценить переход на поддерживаемую 4.x, а не ограничиться патчем до 3.5.x.
3. После смены BOM повторить OSV-аудит и адресно обновить оставшиеся Netty/Bouncy Castle/Jackson; не скрывать уязвимости ignore-правилами без анализа применимости и письменного обоснования.
4. Лишь после устранения или документированного принятия базовой линии включить `fail-on-vuln: true` как блокирующий gate. Перед production-выкладкой сохранить копию БД, проверить кандидатов на её восстановлении и оставить rollback-образы.

Базовый аудит сам по себе не менял backend-образы. Последующие обновления проверены отдельными сборками, интеграционными тестами и staged rollout; состояние релизов описано ниже.

## Кандидат обновления Gateway

После базового аудита Gateway переведён с Boot `3.1.4` / Cloud `2022.0.4` на Boot `3.5.16` / Cloud `2025.0.3` и новые ключи конфигурации маршрутов. 27 тестов, полный CI, повторный OSV-аудит и изолированная проверка на копии рабочей БД прошли; Gateway опубликован отдельно с rollback-образом. В JAR находятся `spring-webflux 6.2.19`, `spring-security-web 6.5.11`, `netty-handler 4.1.135.Final`, `bcprov-jdk18on 1.80.2`. OSV-аудит после одного лишь обновления Gateway показал 151 срабатывание по 42 пакетам (14 Critical, 56 High, 64 Medium, 17 Low) против 236 по 68 пакетам до него. Подробности: [RELEASE_20261011C.md](RELEASE_20261011C.md).

OSV-аудит для коммита `9b71fed` показал 66 срабатываний по 24 пакетам (9 Critical, 21 High, 36 Medium); прежний результат после одного лишь Gateway — 151. В отчёте остаются Tomcat `10.1.55`, Spring Web MVC `6.2.19`, Jackson `2.21.4`, Netty `4.1.135.Final` и другие библиотеки. Проверка остаётся отчётной, не блокирующей.

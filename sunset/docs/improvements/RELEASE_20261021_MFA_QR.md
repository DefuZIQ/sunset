# QR-код для настройки MFA администратора

Дата: 21 октября 2026.

При обязательном подключении TOTP администратор теперь видит QR-код для сканирования в приложении-аутентификаторе. Он создаётся в браузере из уже существующего `otpauthUri`, без передачи секрета сервисам генерации изображений. Ссылка для открытия приложения и ключ для ручного ввода сохранены. После подтверждения одноразового кода QR и ключ удаляются из состояния экрана; резервные коды по-прежнему показываются один раз.

Область изменения: только отдельная админка `/admin/` и `admin.t3ch.pro`. Пользовательскому кабинету эта итерация MFA не добавляет. Auth API и схема БД не менялись.

Проверки: `npm run typecheck`, `npm run build`, 74 frontend unit-теста (включая новый тест QR и его удаления после подтверждения). После публикации прошёл desktop/mobile `npm run test:live` на публичном сайте: главная, каталог, карточка товара, контакты, вход в админку. Подключение реального приложения-аутентификатора не проводилось без живой учётной записи администратора.

Локальный релиз `192.168.1.186`: образ `sunset-web:candidate-mfa-qr-20261021` установлен через `deploy/mfa-qr-candidate/activate-vm.sh`. Предыдущий образ сохранён как `sunset-web:rollback-mfa-qr-20261021`. Публичный релиз: `/srv/sunset/releases/mfa-qr-20261021`; предыдущий `/srv/sunset/releases/catalog-search-20261021` сохранён. Переключение выполнено скриптом `deploy/mfa-qr-candidate/activate-vds.sh` после проверки `nginx -t` и прав доступа. `/`, `/admin/` и публичные страницы ответили успешно.

Откат: на VM пометить `sunset-web:rollback-mfa-qr-20261021` как `sunset-web:latest` и пересоздать только `web` через Compose без сборки. На VDS атомарно переключить `/srv/sunset/current` обратно на `/srv/sunset/releases/catalog-search-20261021`. После каждого отката проверить `/` и `/admin/`.

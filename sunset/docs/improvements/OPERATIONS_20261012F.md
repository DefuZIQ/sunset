# Мониторинг свободного места на сервере

Дата: 12 октября 2026. Код: `49ed35e` в ветке `codex/commerce-platform-v1`.

В профиль наблюдаемости добавлен Node Exporter. Он читает корневую файловую систему хоста через read-only bind mount, не публикует порт наружу и использует отдельную сеть Compose для опроса Prometheus. В Prometheus добавлены сбор `sunset-host` и правила: отсутствие метрик (2 минуты), меньше 15% свободного места (5 минут), меньше 5% (2 минуты). В существующий дашборд Grafana добавлены объём и процент свободного места.

До установки проверены объединённая Compose-конфигурация и конфигурация Prometheus через `promtool`: один файл правил, шесть корректных правил. Исходные конфигурации сохранены в `/home/defuziq/backups/host-disk-monitor-pre-20261012.tar.gz`. Развёрнут только новый `node-exporter`; Prometheus перечитал конфигурацию через SIGHUP, Grafana перезапущена для перечитывания дашборда. Рабочие backend-сервисы и PostgreSQL не пересоздавались.

После установки `up{job="sunset-host"}=1`. Метрика `node_filesystem_avail_bytes{mountpoint="/"}` относится к `/dev/sda2` (ext4), а не к overlay контейнера; при проверке показала 4 306 313 216 байт. Все пять `up{job="sunset-services"}` равны 1, Grafana `/api/health` ответила `database: ok`, публичный сайт остался доступен. Правило `SunsetHostDiskSpaceLow` стало `pending`; через пять минут непрерывного выполнения условия перейдёт в `firing`. Внешняя доставка тревог не настроена, поэтому уведомление пока видно только в Prometheus/Grafana.

Для отката вернуть четыре файла из архива в `/home/defuziq/sunset`, остановить только `node-exporter` через Compose, послать Prometheus SIGHUP и перезапустить Grafana. Данные сайта и БД не затрагиваются.

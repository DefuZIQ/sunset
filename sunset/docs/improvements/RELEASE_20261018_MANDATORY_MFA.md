# Обязательная MFA для администрации — 18 октября 2026

## Политика и переход

Для `ADMIN` и `STAFF` пароль больше не выдаёт полноценный JWT, если TOTP не привязан. Вместо этого Auth Service выдаёт десятиминутный `setupToken`; он пригоден только для настройки TOTP и не проходит проверку сеанса. После проверки первого шестизначного кода создаются восемь одноразовых резервных кодов и выдаётся сеанс с отметкой `mfa_verified`. Резервные коды нужно сохранить до входа в админку. Предыдущие сеансы без подтверждённого фактора отклоняются даже для пользователей, ещё не завершивших привязку.

Вход уже настроенного сотрудника по-прежнему требует TOTP или резервный код. Самостоятельное отключение MFA из UI/API убрано. Покупатели продолжают обычный вход. В рабочей БД перед этим этапом найден один `ADMIN` без MFA и ни одного `STAFF`, поэтому после выпуска единственному администратору потребуется завершить настройку при следующем входе.

Миграция V9 создаёт только таблицу короткоживущих setup-challenge. Секрет TOTP остаётся зашифрованным серверным `MFA_ENCRYPTION_KEY`; его потеря делает существующие факторы невосстановимыми. Восстановление доступа при потере и приложения, и всех резервных кодов требует отдельной проверенной администратором процедуры; автоматического обходного пути нет. Не пересылать резервные коды по почте или в чат поддержки.

## Выполнено

- Перед очисткой проверены текущие контейнеры и образы. Сохранены `latest` и `rollback-20261012b` для пяти backend-сервисов, а также `latest` и `rollback` для `web`.
- Удалены старые кандидатные образы и rollback-теги до `20261012b`, три устаревших `sunset-commerce-build-*` образа, пять завершённых тестовых контейнеров без монтирований и неиспользуемые образы без тегов. Работающие контейнеры, тома и резервные копии не удалялись. Старые образы можно восстановить пересборкой соответствующих Git-ревизий, но их локальные теги больше недоступны.
- На корневом разделе свободное место выросло примерно с 2,3 ГБ (95% заполнения) до 5,0 ГБ (87%). Основное хранилище образов и сборочного кэша — `/var/lib/containerd`; произвольная очистка этого каталога недопустима.
- Для всех десяти сервисов в Compose задан `json-file` с ротацией по `10m` и тремя файлами. Конфигурация проверена `docker compose config --quiet` и нормализованным выводом для каждого сервиса.
- Девять контейнеров, кроме PostgreSQL, пересозданы по одному с ожиданием готовности. У всех девяти через `docker inspect` подтверждены `max-size=10m` и `max-file=3`; пять backend-сервисов healthy. PostgreSQL остался healthy и работает без перезапуска: новая ротация для него вступит в силу только при следующем плановом пересоздании контейнера.
- Публичные главная, каталог, список магазинов и дерево категорий после изменения отвечают HTTP 200.

## Откат конфигурации

Прежние Compose-файлы сохранены в `/home/defuziq/backups/compose-pre-log-20261012c.tar.gz`. Проверить содержимое архива через `tar -tzf` перед восстановлением. Для возврата прежних лимитов восстановить оба файла в `/home/defuziq/sunset`, проверить `docker compose -f docker-compose.prod.yml -f docker-compose.observability.yml config --quiet` и пересоздать нужные сервисы по одному с `--no-deps --no-build --wait --force-recreate`. Возврат конфигурации сам по себе не меняет уже работающие контейнеры.

## Следующее

Добавить мониторинг свободного места и доставку тревог вне сервера. Не выполнять безадресный `docker system prune --volumes`: том PostgreSQL содержит данные магазина. Периодическую очистку образов автоматизировать только после теста сохранения текущего и ближайшего rollback-релиза.

# Автоматическое тестирование

## Полный запуск

Из корня проекта:

```powershell
.\scripts\test-all.ps1
```

Проверка машиночитаемого контракта API (синтаксис JSON, ссылки, уникальность операций, права доступа и соответствие выбранных маршрутов Java-контроллерам):

```powershell
.\scripts\verify-openapi.ps1
```

С браузерными E2E в desktop/mobile Chromium:

```powershell
.\scripts\test-all.ps1 -WithE2E
```

С проверкой уже развёрнутого сайта:

```powershell
.\scripts\test-all.ps1 -WithSmoke -BaseUrl http://192.168.1.186
```

## Изолированный HTTP E2E торговли

Сценарий запускает реальные Gateway, Auth, Product и Order Service против отдельной PostgreSQL с именем `sunset_e2e`. Он регистрирует клиента и тестового администратора, выбирает доступный товар, оформляет самовывоз, проверяет повтор запроса, подтверждает и отменяет заказ, затем сверяет бонусы и остаток. Рабочую БД и работающие сервисы магазина использовать нельзя; тест откажется запускаться, если URL базы не указывает на `sunset_e2e` или Gateway не на локальном адресе.

После сборки JAR-файлов и запуска отдельной PostgreSQL:

```sh
mvn --batch-mode -q package -DskipTests
E2E_JDBC_URL=jdbc:postgresql://127.0.0.1:5432/sunset_e2e \
E2E_DB_USER=sunset E2E_DB_PASSWORD=sunset-e2e-only \
bash scripts/test-commerce-e2e.sh
```

Скрипт поднимает сервисы по очереди, ожидает их готовности и останавливает после теста. База должна быть создана отдельно и удалена после проверки. В GitHub Actions для неё предусмотрен временный PostgreSQL-контейнер и отдельная задача `commerce-http-e2e`.

## Покрытые сценарии

- Gateway: публичный путь без JWT, отказ защищённому запросу без JWT; восемь HTTP-контрактных сценариев с временным downstream-сервером проверяют регистрацию, оформление заказа, передачу состава и способа получения, подмену доверенного `user-id` из JWT, префикс `/api/v1`, query string, одиночный `X-Request-Id`, JSON-ошибки авторизации и отсутствие браузерного Basic-приглашения.
- Auth: регистрация и BCrypt, дубликат email, успешный/ошибочный вход, правила нового пароля.
- Auth + PostgreSQL 16/Testcontainers: миграции на пустой БД, регистрация, роль клиента, JWT, сохранение профиля и смена пароля.
- Order: пустая корзина, неизвестный промокод, недопустимый статус, нулевая корректировка бонусов.
- Order: корректный и поддельный `X-Request-Id`, его отражение в ответе, доступность в MDC во время обработки и очистка после запроса.
- Order + PostgreSQL 16/Testcontainers: Liquibase с чистой БД, оформление и подтверждение заказа, отложенное начисление бонусов, полная компенсация при отмене, идемпотентный повтор, резервирование остатка, конкурентная покупка последнего экземпляра и транзакционный откат при ошибке оплаты.
- Product: обязательность UUID, 404 неизвестного товара, успешная выдача карточки.
- Product + PostgreSQL 16/Testcontainers: все миграции и начальный каталог, дерево категорий, варианты товара и рейтинг из сохранённых отзывов.
- Notification: ограничение размера страницы, счётчик, чтение владельцем и запрет чужому пользователю.
- Newsletter: email-валидация, нормализация/создание, безопасная отписка отсутствующей записи.
- Frontend: запуск приложения, навигация, защита admin-маршрута для гостя, варианты корзины, количество, удаление, очистка и восстановление из `localStorage`.
- Playwright E2E: каталог и фильтрация, поиск, выбор размера и корзина, защита admin-маршрута, оформление доставки и самовывоза, проверка телефона; desktop и mobile Chromium.
- Opt-in HTTP E2E: реальные четыре сервиса и временная PostgreSQL; регистрация, каталог, оформление самовывоза, идемпотентность, администраторское подтверждение, компенсация бонусов, восстановление остатка, запрет гостевого доступа и `X-Request-Id` в каждом ответе.
- Smoke: web, непустой каталог, минимум 100 товаров, категории, карточка товара, акции, публичный `/api/v1/products/all` и HTTP 401 для гостя на прежнем и версионированном пути.

## Что ещё необходимо для production-grade покрытия

- Браузерное оформление с реальными сервисами и отдельной тестовой PostgreSQL: текущие сценарии доставки используют подменённые API-ответы, а HTTP E2E с реальными сервисами покрывает самовывоз.
- Контрактные тесты остальных маршрутов Gateway и бизнес-ответов downstream-сервисов.
- Проверки таймаута резерва и возврата после подтверждения оплаты.
- Тесты внешних интеграций: Ollama, геокодер, будущие платежи и email.

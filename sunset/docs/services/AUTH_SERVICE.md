# Сервис авторизации и профиля

## Ответственность

Регистрация, вход, получение и обновление профиля, смена пароля, хеширование паролей и выпуск JWT. Работает на порту 8081.

## API

- `POST /auth/register` — создание клиента.
- `POST /auth/login` — проверка учётных данных и выдача JWT.
- `GET /auth/profile` — актуальный профиль текущего пользователя.
- `PUT /auth/profile` — изменение имени, контактов, дня рождения и аватара.
- `PUT /auth/profile/password` — смена пароля после проверки текущего.
- `GET /auth/session/validate` — внутренняя проверка действующего сеанса для Gateway (`204` при успехе).
- `POST /auth/logout` — отзыв текущего сеанса (`204` при успехе).
- `GET /auth/iam/me` — действующая роль и список разрешений.
- `GET /auth/iam/staff/{id}/permissions`, `PUT /auth/iam/staff/{id}/permissions` — просмотр и назначение точечных прав (только `ADMIN`).

## Данные

Основная сущность — `User`. Миграции создают пользователей и роли, затем добавляют телефон и роль верхнего уровня. `UserRepository` обеспечивает поиск по email и UUID.
Миграция V5 добавляет `iam_user_permissions` и `iam_access_audit`; V6 — `auth_sessions`, V7 — индекс по `expires_at`. Все опубликованы и проверены на копии PostgreSQL 16.

## Безопасность

Spring Security защищает профильные endpoints. `JwtUtil` выпускает подписанные токены с `jti`, `JwtFilter` сверяет сеанс с БД и создаёт контекст аутентификации. Административные/рабочие токены действуют 15 минут, клиентские — 24 часа. Выход отзывает один сеанс; смена пароля — все сеансы. Пароли хранятся как BCrypt-хеши.

## Ограничения

- Нет подтверждения email/телефона, восстановления пароля, MFA и UI для просмотра/точечного отзыва всех устройств. Записи сеансов удаляются ежедневно через семь дней после истечения.
- Аватар передаётся как поле профиля; отсутствует отдельное объектное хранилище и обработка изображения.
- В `application.properties` присутствуют реквизиты и секреты по умолчанию — их необходимо удалить из репозитория и заменить окружением.

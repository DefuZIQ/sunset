# Сервис заказов и лояльности

## Ответственность

Оформление и просмотр заказов, отмена и редактирование неподтверждённых заказов, статусы, промокоды, бонусные счета и транзакции, магазины самовывоза. Работает на порту 8083.

## Клиентское API

- `POST /order` — создать заказ.
- `GET /order/my` — заказы клиента.
- `GET /order/my/{id}` — подробности заказа.
- `PUT /order/my/{id}` — изменить получение/получателя, пока заказ допускает редактирование.
- `POST /order/my/{id}/cancel` — отменить заказ и выполнить компенсацию бонусов.
- `GET /order/loyalty` — баланс и история лояльности.
- `GET /order/promotions` — активные акции.
- `POST /order/promo/validate` — проверить промокод.
- `GET /order/stores` — активные магазины самовывоза.

## Административное API

- `GET /order/admin/orders` — все заказы.
- `PATCH /order/admin/orders/{id}/status` — смена статуса.
- `GET /order/admin/users` — клиенты и агрегаты.
- `POST /order/admin/users/{id}/bonuses` — ручная корректировка бонусов.
- `GET/POST /order/admin/promotions` — просмотр и создание промоакций.
- `POST /order/stores` — создание магазина; требуется серверная авторизация администратора.

## Правила

Заказ хранит снимок цены и варианта товара. Промокод уменьшает сумму, бонусы могут покрыть до 30% суммы после скидки. Новые бонусы становятся доступными после подтверждения администратором. При отмене платёж, использованные и начисленные бонусы, промокод и остаток компенсируются идемпотентно; повторная отмена возвращает уже отменённый заказ без второй компенсации.

## Ограничения

- Реальный платёжный провайдер пока заменён заглушкой с авторизацией и возвратом.
- Резервирование выполняется атомарным SQL в общей БД; автоматическое освобождение просроченных резервов и межсервисный API ещё не реализованы.
- Получение сведений о клиентах через общую БД нарушает границы сервисов.
- Адрес заказа хранится строкой, поэтому ограничены поиск, аналитика и повторное использование.

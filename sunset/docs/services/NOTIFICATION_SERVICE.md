# Сервис уведомлений и рассылки

## Ответственность

Хранит пользовательские уведомления, состояние прочтения и подписки на email-рассылку. Работает на порту 8084.

## API уведомлений

- `GET /notifications?userId=&limit=` — последние уведомления.
- `GET /notifications/unread-count?userId=` — число непрочитанных.
- `POST /notifications` — создать уведомление.
- `PATCH /notifications/{id}/read?userId=` — отметить прочитанным с проверкой владельца.

## API подписки

- `POST /subscriptions` — подписать email и связать с пользователем при наличии UUID.
- `GET /subscriptions/status` — получить состояние по userId или email.
- `DELETE /subscriptions` — отключить подписку.

## Данные

`Notification` содержит адресата, тип, заголовок, текст, признак прочтения и время создания. `NewsletterSubscription` содержит email, необязательный userId, активность и время обновления.

## Ограничения

- Это хранилище уведомлений, а не полноценный доставщик: нет SMTP, push, SMS, очередей, шаблонов и повторных попыток.
- Клиент передаёт `userId` параметром; для защищённых операций следует использовать идентификатор из JWT.
- Создание уведомления нуждается в service-to-service аутентификации.
- Схема создаётся Hibernate `ddl-auto=update`, а не версионируемой миграцией.

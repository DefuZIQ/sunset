# Сервис уведомлений и рассылки

## Ответственность

Хранит пользовательские уведомления, состояние прочтения и подписки на email-рассылку. Работает на порту 8084.

## API уведомлений

- `GET /notifications?limit=` — последние уведомления текущего пользователя.
- `GET /notifications/unread-count` — число непрочитанных текущего пользователя.
- `POST /notifications` — создать уведомление для текущего пользователя.
- `PATCH /notifications/{id}/read` — отметить прочитанным с проверкой владельца.

## API подписки

- `POST /subscriptions` — подписать email; при валидном JWT Gateway безопасно связывает подписку с пользователем.
- `GET /subscriptions/status` — получить состояние подписки текущего пользователя.
- `DELETE /subscriptions` — отключить подписку текущего пользователя.

## Данные

`Notification` содержит адресата, тип, заголовок, текст, признак прочтения и время создания. `NewsletterSubscription` содержит email, необязательный userId, активность и время обновления.

## Ограничения

- Это хранилище уведомлений, а не полноценный доставщик: нет SMTP, push, SMS, очередей, шаблонов и повторных попыток.
- Защищённые операции используют только доверенный `user-id`, сформированный Gateway из JWT.
- Создание уведомления нуждается в service-to-service аутентификации.
- Схема создаётся Hibernate `ddl-auto=update`, а не версионируемой миграцией.

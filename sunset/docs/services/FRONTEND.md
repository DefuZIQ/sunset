# Сервис Frontend

## Ответственность

React SPA реализует клиентскую витрину, личный кабинет и административный интерфейс. Caddy раздаёт статическую сборку и проксирует API-запросы к Gateway.

## Маршруты

| Маршрут | Экран |
|---|---|
| `#/` | Главная |
| `#/catalog` | Каталог и фильтры |
| `#/catalog/product/:id` | Карточка товара |
| `#/newproducts` | Новинки |
| `#/about`, `#/contacts`, `#/promotions` | Информационные страницы |
| `#/search` | Результаты поиска |
| `#/login`, `#/register` | Вход и регистрация |
| `#/profile/*` | Кабинет, заказы, адреса, избранное, бонусы, настройки, уведомления |
| `#/profile/basket` | Корзина и оформление |
| `#/admin` | Панель администратора |

## Состояние

- `StoreContext` — загрузка каталога и доступ к товарам.
- `CartContext` — варианты товаров и количество, сохранение в `localStorage`.
- `FavoritesContext` — избранное, сохранение в `localStorage`.
- `App` — пользовательская сессия, повторная загрузка профиля и маршрутизация.

## Внешние зависимости

Frontend обращается к относительным путям API, поэтому одинаковая сборка работает за Caddy без жёстко заданного домена. OpenStreetMap используется во встроенной карте. Web Speech API применяется для голосового взаимодействия с помощником, если его поддерживает браузер.

## Сборка

```bash
cd frontend
npm ci
npm run build
```

Сборка выполняется Vite, тесты — Vitest. Результат находится в `frontend/dist` и копируется в образ Caddy.

## Ограничения

- Переход на Vite завершён; следующий этап модернизации — TypeScript, React Query и feature-модули.
- Компоненты `Profile`, `Cart` и `Admin` слишком велики и объединяют UI, запросы и бизнес-правила.
- Адреса и способы оплаты пока не являются полноценными серверными сущностями.
- Нет единой библиотеки форм, схемной валидации и query/cache-слоя.

# API и интеграции

## Общие правила

- Базовый URL совпадает с origin сайта; Caddy передаёт запросы в Gateway. Новые интеграции используют префикс `/api/v1` (например, `/api/v1/products/all`). Прежние пути без префикса пока сохранены для интерфейса и совместимости.
- Формат запросов и ответов — JSON, кроме выдачи статики.
- Защищённые запросы используют `Authorization: Bearer <JWT>`.
- Gateway после проверки токена передаёт `user-id` downstream-сервису.
- Gateway создаёт новый UUID в заголовке `X-Request-Id`, передаёт его сервису и возвращает в ответе, включая ответы 401. Переданный клиентом `X-Request-Id` заменяется; по значению из ответа можно найти запись запроса в логах Gateway и сервиса.
- UUID передаются строкой в стандартном формате.
- Ошибки авторизации, сформированные Gateway (401/403), имеют JSON-поля `code`, `message`, `fieldErrors`, `requestId`, `timestamp`. `requestId` совпадает с доверенным заголовком `X-Request-Id`; это корреляция запросов, а не распределённый trace ID. Ошибки downstream-сервисов пока имеют разные форматы.
- Машиночитаемое описание проверенного ядра клиентских операций находится в [openapi.json](openapi.json). Оно намеренно не объявляет полный охват административных и вспомогательных маршрутов.

Пример ответа Gateway при запросе защищённого ресурса без токена:

```json
{"code":"UNAUTHORIZED","message":"Необходим вход в аккаунт","fieldErrors":{},"requestId":"4cf50b33-44c4-4b34-adc8-1de3970ce8f8","timestamp":"2026-10-05T06:00:00Z"}
```

Для неверного JWT используется `INVALID_TOKEN`, для запрета доступа — `FORBIDDEN`. Текст внутренних ошибок и сам токен в ответ не включаются. Числа, регистрация, товары и остальные ошибки ещё не переведены на эту схему.

## Публичные операции

| Метод и путь | Назначение |
|---|---|
| `POST /auth/register` | Регистрация |
| `POST /auth/login` | Вход |
| `GET /products/all` | Каталог |
| `POST /products/by-uuid` | Карточка товара |
| `GET /products/reviews/{id}` | Отзывы |
| `GET /products/categories/tree` | Категории |
| `GET /order/promotions` | Акции |
| `POST /order/promo/validate` | Проверка промокода (сейчас требует JWT в Gateway) |
| `GET /order/stores` | Магазины (сейчас требует JWT в Gateway) |
| `POST /subscriptions` | Подписка |
| `GET /subscriptions/status` | Статус подписки |
| `POST /assistant/chat` | AI-консультант |

## Административные операции

Пути `/products/admin/**` и `/order/admin/**` предназначены только для роли `ADMIN`. Проверка должна выполняться Gateway и самим владельцем ресурса. Полный список приведён в спеках Product и Order.

## Идемпотентность

Создание заказа принимает `idempotencyKey` в JSON-теле, не заголовок `Idempotency-Key`. Повтор создания с тем же непустым ключом для клиента возвращает прежний заказ. Повтор отмены уже отменённого заказа безопасен. Общий заголовок `Idempotency-Key` для остальных операций пока не реализован.

## Версионирование

Префикс `/api/v1` доступен для существующих HTTP-операций: Gateway удаляет его перед авторизацией и передачей запроса текущим сервисам. Метод, query string, тело запроса, JWT и правила доступа остаются теми же. Старые пути пока работают; дата их отключения не назначена. Несовместимые изменения должны создавать следующую версию, совместимые поля добавляются опционально. OpenAPI пока покрывает 15 основных операций; генерация клиентских типов, полный охват маршрутов и единый формат ошибок всех сервисов ещё не реализованы.

# API и интеграции

## Общие правила

- Базовый URL совпадает с origin сайта; Caddy передаёт запросы в Gateway.
- Формат запросов и ответов — JSON, кроме выдачи статики.
- Защищённые запросы используют `Authorization: Bearer <JWT>`.
- Gateway после проверки токена передаёт `user-id` downstream-сервису.
- Gateway создаёт новый UUID в заголовке `X-Request-Id`, передаёт его сервису и возвращает в ответе, включая ответы 401. Переданный клиентом `X-Request-Id` заменяется; по значению из ответа можно найти запись запроса в логах Gateway и сервиса.
- UUID передаются строкой в стандартном формате.
- Ошибки должны иметь единый будущий формат: `code`, `message`, `fieldErrors`, `traceId`, `timestamp`.

| Метод и путь | Назначение |
|---|---|
| `POST /auth/register` | Регистрация |
| `POST /auth/login` | Вход |
| `GET /products/all` | Каталог |
| `POST /products/by-uuid` | Карточка товара |
| `GET /products/reviews/{id}` | Отзывы |
| `GET /products/categories/tree` | Категории |
| `GET /order/promotions` | Акции |
| `POST /order/promo/validate` | Проверка промокода |
| `GET /order/stores` | Магазины |
| `POST /subscriptions` | Подписка |
| `GET /subscriptions/status` | Статус подписки |
| `POST /assistant/chat` | AI-консультант |

## Защищённые клиентские операции

| `PUT /auth/profile/password` | Смена пароля |

## Административные операции

Пути `/products/admin/**` и `/order/admin/**` предназначены только для роли `ADMIN`. Проверка должна выполняться Gateway и самим владельцем ресурса. Полный список приведён в спеках Product и Order.

## Идемпотентность

Создание заказа, списание бонусов, отмена и изменение статуса должны принимать `Idempotency-Key`. Повтор с тем же ключом обязан вернуть прежний результат без повторного списания/начисления. В текущей версии это требование реализовано не полностью.

## Версионирование

Рекомендуемый целевой префикс — `/api/v1`. Несовместимые изменения создают следующую версию, совместимые поля добавляются опционально. OpenAPI-файл должен быть источником контрактов и клиентских типов.

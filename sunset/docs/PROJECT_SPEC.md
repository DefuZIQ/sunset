# Общий спек проекта SUNSET

## 1. Назначение

SUNSET — интернет-магазин одежды с клиентской витриной и административным интерфейсом. Система позволяет просматривать каталог, фильтровать товары, выбирать цвет и размер, добавлять позиции в избранное и корзину, оформлять доставку или самовывоз, применять промокоды и бонусы, отслеживать и редактировать неподтверждённые заказы. Администратор управляет товарами, вариантами, остатками, заказами, клиентскими бонусами и промоакциями.

## 2. Пользовательские роли

| Роль | Возможности |
|---|---|
| Гость | Каталог, поиск, карточки, отзывы, акции, контакты, AI-помощник, локальная корзина и избранное |
| Клиент | Всё гостевое плюс профиль, адреса, оформление, заказы, бонусы, уведомления, подписка |
| Администратор | Управление товарами, вариантами и остатками; просмотр заказов и клиентов; статусы заказов; корректировки бонусов; промоакции |

## 3. Архитектура

```text
Браузер
  │ HTTP :80
  ▼
Caddy + React SPA
  │ /auth /products /order /notifications /subscriptions /assistant
  ▼
Spring Cloud API Gateway :8080
  ├── auth-service :8081
  ├── product-service :8082
  ├── order-service :8083
  ├── notification-service :8084
  └── Ollama :11434 (внешний локальный процесс)
        │
        └── PostgreSQL 16 (единый экземпляр и общая БД)
```

Сервисы запускаются Docker Compose. Внешнему пользователю открыт Caddy на порту 80; остальные компоненты доступны внутри Docker-сети. JWT создаётся сервисом авторизации и проверяется шлюзом. Шлюз передаёт идентификатор пользователя в заголовке `user-id`.

## 4. Технологии

- Frontend: React 19, React Router 7, Context API, CSS, Vite 7, Vitest и Playwright.
- Backend: Java 17, Spring Boot, Spring Security, Spring Data JPA.
- Gateway: Spring Cloud Gateway/WebFlux.
- Данные: PostgreSQL 16, Liquibase.
- AI: Ollama с настраиваемой моделью, по умолчанию `qwen2.5:0.5b`.
- Web/Reverse proxy: Caddy 2.
- Сборка: Maven multi-module и npm.
- Развёртывание: Docker Compose.

## 5. Основные бизнес-процессы

### Каталог и покупка

1. Frontend получает товары из `product-service`.
2. Пользователь выбирает конкретную комбинацию цвета и размера.
3. Корзина хранит товар, вариант и количество в `localStorage`.
4. При оформлении frontend отправляет позиции, контакт, способ получения, промокод и бонусы в `order-service`.
5. Сервис заказа фиксирует снимок состава и стоимости, создаёт операции лояльности и очищает корзину после успешного ответа.

### Авторизация

1. Регистрация или вход выполняются через `/auth`.
2. Клиент получает JWT и сохраняет его вместе с кратким профилем.
3. При запуске SPA профиль повторно запрашивается с сервера.
4. Gateway проверяет JWT на защищённых маршрутах и добавляет `user-id`.

### Администрирование

Маршрут `#/admin` доступен только пользователю с ролью `ADMIN`. UI объединяет каталог, остатки, заказы, пользователей и промоакции. Серверные административные операции должны дополнительно проверять роль, а не полагаться только на скрытие интерфейса.

## 6. Нефункциональные требования текущей версии

- Интерфейс адаптируется к мобильным и настольным экранам.
- Денежные значения показываются в рублях.
- Каталог поддерживает более 100 товаров, категории, подкатегории, пол, размеры, цвета, рейтинг и отзывы.
- Состояние корзины, избранного и части адресов сохраняется локально в браузере.
- Миграции выполняются автоматически при старте соответствующего сервиса.
- Контейнеры автоматически перезапускаются, кроме случаев явной остановки.

## 7. Известные архитектурные ограничения

- Микросервисы используют одну физическую БД и могут обращаться к чужим таблицам; изоляция владения данными неполная.
- Часть пользовательских данных хранится только в `localStorage`, поэтому не синхронизируется между устройствами.
- Конфигурационные файлы содержат небезопасные значения по умолчанию и устаревшие локальные реквизиты подключения.
- API не имеет версионирования и опубликованной OpenAPI-схемы.
- Автоматические тесты в основном проверяют только запуск контекста.
- В frontend отсутствуют единый API-клиент, дизайн-токены и централизованная обработка ошибок.

## 8. Критерии готовности релиза

- Все Maven-модули и production-сборка frontend собираются без ошибок.
- Критические сценарии входа, каталога, корзины, оформления, отмены и админки проходят интеграционные тесты.
- Миграции успешно применяются на чистой и существующей БД.
- Секреты поступают только через окружение или secret manager.
- Есть резервная копия БД и проверенный сценарий восстановления.
- Healthcheck каждого контейнера сообщает фактическую готовность.
